# /cheat-approve — 用户认可样本沉淀

这个子 skill 负责一件事：把用户明确说“这是我认可的内容”的稿子，保存为以后写稿时可参考的个人样本。

它学习的是**表达方式和写法**，不是把一条内容直接变成永远正确的模板，也不是用播放量反推语气。

## 核心规则

1. **明确认可才写入**。例如“这条我认可”“这就是我想要的语气”“以后按这个风格来”“把这条沉淀到 Skill”。
2. “谢谢”“收到”“先这样”“数据不错”不等于认可。语义不明确时，先问一句是否要把它作为个人样本保存。
3. 只保存用户指向的最终版本。没有路径时，只有在当前对话刚刚生成且唯一的稿件时才自动取用；有多个候选必须询问路径。
4. **不覆盖原稿，不覆盖已有样本**。每次认可都创建新的样本文件，重复认可也保留为独立版本并标明来源。
5. 认可样本进入创作 context，但不进入 `rubric_notes.md`，也不改变盲预测结果。播放量和复盘证据仍只能通过 `cheat-retro` / `cheat-bump` 进入校准链路。
6. 不认可、否定、要求重写的内容不写入 `approved_samples/`、`voice_profile.md` 或正式 pattern。

## 输入与落盘位置

| 内容 | 位置 | 用途 |
|---|---|---|
| 原始认可样本 | `approved_samples/YYYY-MM-DD_<source-stem>[_vN].md` | 保留用户认可的完整文本，便于追溯 |
| 语气档案 | `voice_profile.md` | 从样本中提炼已确认的语气、节奏、用词和禁区 |
| 写作 pattern | `script_patterns.md` | 记录结构性写法；单样本先标“用户认可，待验证” |

如果项目还没有 `voice_profile.md` 或 `approved_samples/`，先按模板创建，不覆盖已有文件。

来源可以是：

- `scripts/*.md` 或 `videos/*/script.md`；
- 当前对话中用户贴出的最终稿；
- 用户明确指向的成片（`.mp4` / `.mov` 等）。成片没有现成脚本时，先用可用的转写工具提取口播；无法可靠转写就请用户提供文字，不凭画面猜台词。

如果用户只认可某一部分（例如“开头这段可以，后面不要学”），只保存被点名的片段，并在样本头部标记 `scope: excerpt`；没有明确范围时，正向认可默认指向整条。

## Workflow

### Phase 0：校验认可与来源

1. 检查项目根目录是否有 `.cheat-state.json`。没有就提示先初始化。
2. 从用户消息提取明确认可信号。只有正向、指向具体稿件的表达才通过；不要根据语气猜测。
3. 解析来源路径：允许 `scripts/*.md`、`videos/*/script.md`、用户在当前对话中明确贴出的最终稿，以及用户明确指向的成片文件。
4. 读取来源并确认它是最终内容。若文件含“Draft by Claude / 必须改写”且用户没有说明已改成最终稿，提醒一次后仍可按用户明确指令保存。
5. 如果来源是成片，优先使用可靠转写结果；把画面 / 剪辑上用户明确认可的特征单独记入 `voice_profile.md`，不要把未确认的视觉推断写成语气规则。

### Phase 1：保存不可变样本

1. 生成不冲突的文件名；若同名存在，追加 `_v2`、`_v3`，绝不覆盖。
2. 写入样本文件：保留正文原文（或明确认可的片段），并在文件头记录 `source`、`approved_at`、`approval_signal`、`scope`、`status: active`。不要把播放量、评论数等实绩复制进语气档案。
3. 原来源文件保持不变。样本文件一旦写入，后续只能新增版本，不能静默改写。

建议的样本头部：

```markdown
---
source: scripts/2026-08-30_example.md
approved_at: 2026-08-31T12:00:00+08:00
approval_signal: user-explicit
scope: full
status: active
---

[用户明确认可的原文]
```

### Phase 2：更新语气档案

在 `voice_profile.md` 追加本次样本的索引，并只写**能从原文直接举证**的观察：

- 语气：例如“先讲亲历，再给判断”；不要写空泛的“自然、有感染力”。
- 节奏：例如“短句为主，关键判断单独成句”。
- 词汇：记录用户反复使用或明确保留的口头连接词。
- 禁区：只记录用户明确反感或样本明显避开的表达，标注来源。

单个样本产生的观察放入“已认可、单样本待验证”，不要冒充稳定规律。用户直接说过的偏好放入“用户明确指定”，与样本推断分开。

### Phase 3：更新写作 pattern

从样本提炼结构时：

- 追加到 `script_patterns.md` 的“用户认可样本”或“新发现的 Pattern”段；
- 标注 `User-approved, single-sample`；
- 写明来源文件和触发条件；
- 不自动改 `rubric_notes.md`，不把一个样本升格为通用模板。

### Phase 4：回报与边界

完成后明确告诉用户：

```text
已沉淀：approved_samples/<file>.md
已更新：voice_profile.md、script_patterns.md
这条会作为后续写稿的高优先级参考；未认可的稿子不会进入学习库。
```

如果用户说“不要学这条”“撤销这条样本”，不要删除历史文件；同时把样本头部和 `voice_profile.md` 索引都标为 `revoked`，后续生成忽略它。除非用户明确要求永久删除并确认准确路径，否则不做不可恢复删除。

## 后续生成时的读取优先级

`cheat-seed` 写新稿时按以下顺序使用 context：

1. `voice_profile.md` 中“用户明确指定”和“已认可、已复现”的规则；
2. 最近 3 条 `approved_samples/` 中的原文片段；
3. `script_patterns.md` 中用户认可的 pattern；
4. 用户历史拍摄稿、对标账号和通用 starter rubric。

已认可样本是参考，不是硬模板。每次新稿仍要围绕新的真实经历和主承诺重写。

## Refusals

- 「这条播放量高，所以自动学成我的语气」→ 拒绝自动学习；询问用户是否明确认可它的表达方式。
- 「把所有历史稿都塞进语气库」→ 拒绝；只收录用户点名认可的样本。
- 「把这条样本的真实数据写进 rubric_notes.md」→ 拒绝；实绩走 `cheat-retro`，避免污染盲预测。
